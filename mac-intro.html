The basics

What you're looking at

When you first turn on the Mac and finish setup, you land on the desktop. Here's what everything is:

The menu bar

The strip at the very top of the screen. It always belongs to whichever app is active at the moment. The leftmost item is the Apple menu —  — which is where you find Shut Down, Restart, and System Settings. On the right you'll see the time, battery, and Wi-Fi.

The Dock

The row of icons at the bottom of the screen. Clicking an icon opens that app. If a dot appears beneath an icon, the app is currently running. You can drag icons in and out of the Dock to customise it. Right-click any icon for options including keeping it in the Dock permanently.

Apps

On a Mac, closing a window doesn't necessarily quit the app — the app keeps running in the background (you'll see the dot under its Dock icon). To actually quit: press ⌘ Q or use the menu bar → AppName → Quit. This trips up people switching from Windows.

Closing ≠ quitting

On Windows, closing the last window kills the app. On Mac, it doesn't. The app is still running, still using memory, until you press ⌘ Q. If something feels slow or your battery is draining fast, check whether you have twenty apps quietly running in the background.

Mac vs Windows key names

Command ⌘ is the Mac equivalent of Ctrl on Windows. Option ⌥ is Alt. The keyboard symbol ⇧ is Shift. Where Windows uses Ctrl+C to copy, Mac uses ⌘+C.

The MacBook Neo chip

Your machine runs an A18 Pro chip — the same silicon that powers Apple's latest iPhones. It's fast, efficient, and very capable. The unified memory means the CPU and GPU share the same 8 GB pool, so it's worth not running too many heavy apps at once. More on that in the coding setup later.

If the trackpad feels too fast or slow, go to System Settings → Trackpad and adjust the tracking speed. Scrolling direction can also be changed here if the default ("natural") feels backwards.

Search

Spotlight — your best friend

Press ⌘ Space from anywhere. A search bar appears in the middle of the screen. Start typing.

Spotlight finds apps, files, emails, contacts, and can do quick calculations and unit conversions. Once you get used to it, you'll open most things this way rather than clicking through the Dock or Finder.

Things Spotlight is great for

  • Opening apps — type "Terminal", hit Enter. No Dock hunting.
  • Finding files — type the filename, or part of it.
  • Quick maths — type 15 * 8 and it shows the answer inline.
  • Unit conversion — type 100 USD in GBP or 5 km in miles.
  • Opening System Settings panels — type "Keyboard" and jump straight there.
Pro tip

For a more powerful version of Spotlight with more features, many developers install Raycast (free) or Alfred later in their career. You don't need it now, but it's worth knowing it exists.

Files

Finder and files

Finder is the Mac's file manager — the equivalent of Windows Explorer. The icon is the blue-and-white face in your Dock.

Finding your way around

The left sidebar shows your most-used locations: Desktop, Documents, Downloads, and any connected drives. Click one to see its contents.

The top of the window has a toolbar with view options:

  • Icon view — thumbnails, good for photos
  • List view — rows with file details, best for code projects
  • Column view — drill down through folders side by side

Important Finder settings

These two settings will save you genuine confusion once you start coding:

1

Show file extensions

Open Finder → click Finder in the menu bar → Settings → Advanced → tick "Show all filename extensions". Without this, you can't tell notes.txt from notes.py — they look identical.

2

Show the path bar

In any Finder window: View menu → Show Path Bar. A breadcrumb trail appears at the bottom of the window telling you exactly where you are. Essential when you're working with folders inside folders.

Hidden files

Files and folders whose names start with a dot (like .git or .venv) are hidden from Finder by default. You can toggle them with ⌘ ⇧ . (Command + Shift + full stop). You'll see them in the terminal all the time, so it's useful to know they exist.

Configuration

System Settings

Open with  (Apple menu, top-left) → System Settings. Or type "System Settings" in Spotlight.

It's organised into categories in a sidebar on the left. Here are the ones you'll visit most:

Apple ID

Sign in with your Apple ID to get iCloud Drive, iMessage on your Mac, the App Store, and backup. If you already use an iPhone, use the same Apple ID.

Wi-Fi

Connect to your home network here. Once connected, the Mac remembers it and reconnects automatically.

Displays

Adjust the resolution and scaling. The default "Looks like 1512 × 982" setting is good for most work. Increase text size here if things feel small.

Keyboard

Two things to change before you start coding:

  • Key Repeat Rate → drag to Fast. You'll be holding down arrow keys a lot. Slow repeat is maddening.
  • Delay Until Repeat → drag to Short.

Trackpad

Adjust tracking speed here. Many coders turn it up to near the maximum. Also check Secondary click is set to "Click or Tap with Two Fingers" so right-click works.

Notifications

You'll want to turn off most notifications when coding. Use Focus modes (also in System Settings) to silence everything while working. ⌘ ⇧  N won't work but you can enable a Focus mode from the menu bar's Control Centre icon.

Privacy & Security

When you first run a downloaded app or terminal tool, macOS may block it and show a security warning. Go here and click Open Anyway. This happens a lot with developer tools — it's normal and expected.

The terminal

The Terminal — first look

The Terminal is a text window where you type commands directly at your computer. It's where almost all developer work happens. It sounds old-fashioned; it is, and it's also far more powerful and precise than clicking through windows.

To open it: Press ⌘ Space, type "Terminal", press Enter. A window appears with a prompt — something like:

tom@MacBook-Pro ~ %

That's your computer waiting for a command. The ~ means you're in your home folder. The % is the prompt itself — it just means "ready".

Your first command

Type this and press Enter — it means "print working directory" (i.e. where am I right now?):

pwd

It will print something like /Users/tom. That's your home folder on disk.

Why the terminal exists

Some things can only be done from the terminal: installing developer tools, running programs, creating and moving files in bulk, talking to servers. Once you get comfortable with it, many things are faster here than in any app.

The full guide to terminal commands is in the Install tools page. For now, just know where to find it and that it doesn't bite.

One rule

If you ever find a command online that starts with sudo, pause and read it carefully before running it. sudo means "run this as administrator" — it has the power to change anything on your machine. Copy-pasting random sudo commands is how things get broken. If in doubt, ask first.

Before you code

Settings to change now

A short checklist. Do these once and you won't have to think about them again.

1

Show file extensions in Finder

Finder → Settings → Advanced → "Show all filename extensions". Already covered above, but worth repeating — this one will catch you out if you skip it.

2

Speed up key repeat

System Settings → Keyboard → Key Repeat Rate to Fast, Delay Until Repeat to Short. You'll feel the difference immediately.

3

Enable three-finger drag

System Settings → Accessibility → Pointer Control → Trackpad Options → enable "Use trackpad for dragging" and set style to "Three Finger Drag". Makes moving windows and selecting text much easier.

4

Keep the Dock on the left or bottom

The default is the bottom, which is fine. If you want more vertical screen space while coding, move it to the left: System Settings → Desktop & Dock → Position on screen → Left.

5

Check for macOS updates

System Settings → General → Software Update. A fresh Mac may have an update waiting. Get this out of the way now rather than during a coding session.

Memory note for the MacBook Neo

With 8 GB of unified memory, keep Chrome for debugging only — use Safari for everyday browsing. Running Chrome with dozens of tabs alongside VS Code will push the machine into swap and everything will feel sluggish. Browser discipline is one of the most practical habits you can build.
