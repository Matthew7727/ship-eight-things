Step 02

Install tools

Everything you need to write, run, and share code. You do this once and never again.

Before you start

Every command on this page is typed into a terminal window. On Mac, open Terminal with ⌘ Space, type "Terminal", press Enter. On Windows, open your Ubuntu WSL window from the Start menu. Each command is followed by pressing Enter to run it. Wait for each one to finish before running the next.

Mac or Windows?

If you're on a Mac, work straight down the page. If you're on Windows, start with the WSL section below, do the setup inside Ubuntu, then skip the Apple developer tools and Homebrew sections.

Windows path

Enable WSL and use Ubuntu

If you're on Windows, don't do this guide in PowerShell or Command Prompt. Use WSL (Windows Subsystem for Linux) so the terminal, paths, package manager, and Python setup behave like a normal developer machine.

1 — Install WSL

Open PowerShell as Administrator and run:

wsl --install -d Ubuntu

Windows may ask you to restart. Let it. When Ubuntu opens for the first time, create your Linux username and password. From this point on, do the guide inside Ubuntu, not in PowerShell.

2 — Update Ubuntu

sudo apt update
sudo apt upgrade -y

Your password won't show as you type it. That's normal.

3 — Install the tools you need inside WSL

sudo apt install -y python3 python3-pip python3-venv nodejs npm git

This gives Ubuntu its own copy of Python, pip, Node.js, npm, and Git. Keep your coding work inside Linux, not under random Windows folders.

4 — Install VS Code on Windows

Back in a normal Windows terminal, install VS Code:

winget install --id Microsoft.VisualStudioCode -e

Then open VS Code, install the Remote - WSL extension, and also install the same four extensions listed later on this page: Python, Pylance, Ruff, and GitLens.

5 — Check WSL can open VS Code

Back in Ubuntu, run:

code --version

If that prints a version number, you're set. If it says code isn't found, open any folder from VS Code using the Remote - WSL extension once, then try again.

Step 1

Apple's developer tools

This installs Apple's command-line developer tools — a collection of low-level programs that almost everything else depends on. Git, compilers, and other tools won't work without it.

Type this command and press Enter:

xcode-select --install

A dialogue box will pop up asking you to install. Click Install (not "Get Xcode" — you don't need the full Xcode app). This takes a few minutes depending on your internet connection. When it says "The software was installed", you're done.

Confirm it worked:

xcode-select --version

You should see something like xcode-select version 2395. Any version number means success.

Step 2

Homebrew

Homebrew is the package manager for macOS. Think of it as an app store for developer tools — it lets you install, update, and remove programs with a single command. Almost everything you'll install goes through Homebrew.

Copy this entire command (it's long — that's normal) and paste it into Terminal, then press Enter:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

It will ask for your Mac login password. Type it — you won't see the characters as you type, that's normal. Press Enter when done. The installer runs for a few minutes.

When it finishes, it will print two more commands near the bottom of the output. They start with echo and eval. Run both of them. They tell your terminal where to find Homebrew. On Apple Silicon, Homebrew lives at /opt/homebrew rather than the old location, and your terminal needs pointing at it.

Here's what those two lines look like (yours will be identical):

echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

Let's break down what those two lines do, because understanding them is worth it:

  • echo '...' >> ~/.zprofile — the echo command prints text, and the >> means "append it to the end of this file" rather than printing it on screen. ~/.zprofile is a file that runs automatically every time you open a new terminal window. So this line is adding the Homebrew setup to that startup file, meaning it'll work forever, not just in this session.
  • eval "$(...)" — runs the Homebrew setup right now, in the current terminal session, so you don't have to close and reopen it first.

Check it worked:

brew --version

You should see Homebrew 4.x.x or similar. If you see "command not found", close Terminal completely, reopen it, and try again.

Updating Homebrew later

Run brew update to fetch the latest package list, and brew upgrade to update everything. Do this every month or so. Run brew cleanup to remove old versions and free up disk space.

Step 3

Python

macOS comes with a Python, but it belongs to the operating system and you shouldn't build on top of it — Apple may change or remove it in a future update. Install your own fresh copy instead.

If you're on Windows with WSL, you already installed Python inside Ubuntu above, so here you're just checking it worked.

On Mac, install Python via Homebrew:

brew install python

Check it installed:

python3 --version

You should see Python 3.12.x or newer. The 3 in python3 matters — on macOS, python (without the 3) may still point to the system Python.

Also check pip3, which is Python's package installer (you'll use it constantly):

pip3 --version

You'll see a version number and a path. On Mac, the path should include homebrew somewhere in it — confirming you're using the Homebrew Python, not the system one. In WSL, it will point somewhere inside Ubuntu instead.

What is pip?

pip stands for "Pip Installs Packages". It's how you add third-party Python libraries to your project. For example, pip3 install requests adds a library for making HTTP requests. You'll use this from Project 3 onwards.

Step 4

Node.js & npm

Node.js lets you run JavaScript outside of a browser — directly on your machine. You'll use it from Project 5 onwards when you start building web apps. npm (Node Package Manager) comes bundled with it and works like pip but for the JavaScript world.

If you're on Windows with WSL, you already installed both inside Ubuntu above, so this section is just the version check.

On Mac, install both via Homebrew:

brew install node

Check Node.js installed:

node --version

You should see v22.x.x or newer.

Check npm is there too:

npm --version

You should see a version number like 10.x.x.

You won't use Node heavily at first

The first four projects are pure Python. Node.js is here because it's easier to install it now than to interrupt a project later. When it becomes relevant, the project guide will explain it.

Step 5

Git

Git is version control — it tracks every change you make to your code, lets you go back in time, and makes it possible to share code with others. It's the single most important tool in professional software development. You'll use it every session.

If you're on Windows with WSL, use the Ubuntu copy of Git, not Git for Windows, so the commands match the rest of the guide.

On Mac, the built-in Git is old. Install a current one:

brew install git

Check it installed:

git --version

You should see git version 2.4x.x or similar. If it still shows 2.39, close and reopen Terminal so it picks up the Homebrew version.

Tell Git who you are

Git needs to know your name and email address to attach to your commits. Use the same email you'll use for GitHub.

git config --global user.name "Tom"
git config --global user.email "your@email.com"
git config --global init.defaultBranch main

Let's read those commands:

  • git config --global — changes a setting that applies to all your git repos on this machine (--global means "not just this folder, everywhere").
  • user.name "Tom" — sets the name that appears on your commits. Swap in your actual name.
  • user.email "..." — sets the email. Must match your GitHub account or commits won't link to your profile.
  • init.defaultBranch main — makes new repos start with a branch called main (the modern default) instead of the older master.

Check your settings saved:

git config --list

You'll see a list of your settings. Scroll up to find user.name and user.email.

Step 6

VS Code

VS Code (Visual Studio Code) is the code editor. It's free, fast, runs on everything, and is by far the most widely used editor in industry today. This is where you'll write all your code.

On Windows, VS Code itself runs on Windows but your project folder should live in WSL. Open it through the Remote - WSL extension so the editor talks to Ubuntu, not to PowerShell.

On Mac, install it with Homebrew:

brew install --cask visual-studio-code

The --cask flag tells Homebrew to install a full Mac application (as opposed to a command-line tool). This takes a minute or two to download.

Open VS Code when it's done. You'll find it in your Applications folder or via Spotlight (⌘ Space → "VS Code").

Install the shell command

This lets you open VS Code from the terminal by typing code ., which you'll do constantly.

On Mac, press ⇧ ⌘ P to open the Command Palette, type "shell command", and click Shell Command: Install 'code' command in PATH. On Windows + WSL, the VS Code installer and Remote - WSL extension normally make code available inside Ubuntu automatically.

Test it works:

code --version

Any version number means it's working.

Install exactly these extensions

Extensions add language support, linting, and extra tools. Every extension uses a small amount of memory, so install only what you need. For now, install these four and nothing else:

Extension nameWhat it does
Python (by Microsoft)Core Python language support — syntax highlighting, running files, test integration
PylanceSmart autocomplete and inline error highlighting for Python
RuffCatches style mistakes and formats your code on save — keeps your code readable without you thinking about it
GitLensShows the history of every line — who changed it and when. Invaluable once you're working on a project for a few weeks

To install: click the Extensions icon in VS Code's left sidebar (four squares), search for each name, click Install.

Memory discipline

Each extension costs memory on your 8 GB machine. Only install more later if something is genuinely annoying you. "Looks nice" is not a reason to install an extension.

Two settings to change in VS Code

Open Settings with ⌘ , on Mac or Ctrl , on Windows. Search for each of these and update them:

  • Format on Save — set to checked. This makes Ruff format your code every time you save. You'll want this.
  • Word Wrap — set to on. Long lines won't run off the right edge of the screen.
Step 7

Terminal survival kit

You need about ten commands to do most of what this guide requires. Everything else you can look up when you need it. Here's what they are and exactly what each one does:

CommandWhat it doesExample
pwdPrint Working Directory — shows you where you are right nowpwd → /Users/tom/code
lsList — shows the files and folders in the current directoryls shows the contents, ls -la shows hidden files too
cdChange Directory — moves you into a foldercd projects to go in, cd .. to go up one level, cd ~ to go home
mkdirMake Directory — creates a new foldermkdir my-project
touchCreates an empty filetouch hello.py
rmRemove — deletes a file permanently (no Trash)rm old-file.py
mvMove (also renames)mv old-name.py new-name.py
cpCopy a filecp file.py backup.py

Two habits worth forming immediately

Press Tab to autocomplete file and folder names. It prevents typos and is much faster. Press the up arrow to get your last command back without retyping it. These two habits save enormous time.

How paths work

A path is an address for a file or folder on your disk. Understanding paths removes a lot of confusion.

  • / at the very start means the root of the disk (the very top level). /Users/tom/code/project/main.py is an absolute path — it works from anywhere.
  • A path without a leading / is a relative path — it's relative to where you are now. If you're already in /Users/tom/code/, then project/main.py means the same file.
  • ~ is a shortcut for your home folder: /Users/tom. So ~/code means /Users/tom/code.
  • . means "the current folder". ls . is the same as ls.
  • .. means "the folder above this one". cd .. moves you up one level.
Verification

Checking everything works

Run the set for your machine. Each command should print a version number — no error messages.

Mac

xcode-select --version  # Apple developer tools
brew --version          # Homebrew
python3 --version       # Python
pip3 --version          # Python's package manager
node --version          # Node.js
npm --version           # Node's package manager
git --version           # Git
code --version          # VS Code shell command

Windows + WSL

python3 --version       # Python inside Ubuntu
pip3 --version          # Python's package manager
node --version          # Node.js inside Ubuntu
npm --version           # Node's package manager
git --version           # Git inside Ubuntu
code --version          # VS Code talking to WSL

If any of them say "command not found", go back to that section and check you ran every step. On Mac, the most common cause is missing the Homebrew path commands. On Windows, the most common cause is running the command in the wrong place — PowerShell instead of Ubuntu.

If something went wrong

Close Terminal completely, reopen it, and try the failing command again. A fresh terminal window picks up any path changes that the current one might have missed. If it still fails, check you ran the command exactly as written — copy-paste it rather than typing by hand.

What to do next

Now that your machine is set up, go to the main guide to set up Git and GitHub, and create your first repo. That's the final piece before Project 1 starts.
