Session 1

What actually happens when you visit a page

Let's trace exactly what happens when you type a URL and press enter. First, DNS translates the hostname into an IP address — a number that locates the server. Your browser opens a TCP connection to that IP on port 80 (HTTP) or 443 (HTTPS). Over that connection it sends an HTTP request. The server sends back an HTTP response containing HTML. Your browser parses and renders it. Then the connection closes.

A port is like a numbered door on a server — different services listen on different ports. Web servers listen on 80 or 443. When Flask runs locally it uses port 5000 by default because 80 requires system permissions. That's why you visit localhost:5000 — "connect to my own machine on port 5000".

The last part of the cycle matters: the web is stateless. Every request stands alone. Anything remembered between requests has to be deliberately stored — which is why sessions and databases exist.

The web is stateless

Every time your browser loads a page, it's a completely fresh request — the server has no memory of your previous visit. This isn't a quirk; it's a fundamental design of HTTP. Anything you want to persist between pages (who's logged in, what's in a basket, what a user typed) must be explicitly stored somewhere: a database, a session cookie, or URL parameters. If something disappears when you refresh, this is why.

pip install flask
from flask import Flask
app = Flask(__name__)

@app.route("/")
def home():
    return "Hello from Flask"

if __name__ == "__main__":
    app.run(debug=True)

Run it and visit localhost:5000. The @app.route("/") line says "when someone asks for the root URL, run this function". debug=True reloads on save and shows errors in the browser — helpful now, but in production it would expose your source code and internal state to anyone who triggers an error. It must be off before deployment, read from an environment variable.

Build this

Flask running locally with three routes: /, /about, and /health (returns {"status": "ok"} as JSON — this is a standard pattern for checking if a service is alive). Make sure debug=True is read from an environment variable, not hardcoded.

You should now be able to

You can explain what a request and a response are, describe what happens at each step when you visit a URL, and add a new route. You know why debug mode must be off in production.

Session 2

Enough HTML

HTML describes structure. Tags wrap content, most come in pairs.

<!DOCTYPE html>
<html>
<head>
  <title>Expenses</title>
</head>
<body>
  <h1>My expenses</h1>
  <p>A paragraph.</p>
  <ul>
    <li>Coffee — £3.40</li>
  </ul>
  <a href="/add">Add one</a>
</body>
</html>

The dozen tags you need: h1–h3 headings, p paragraph, ul/li lists, a links, div generic container, form/input/button for input, table/tr/td for tables.

Flask looks for HTML files in a folder called templates:

from flask import render_template

@app.route("/")
def home():
    return render_template("index.html")
Build this

A templates/index.html with a heading and a hardcoded list, served by Flask.

You should now be able to

You can write basic HTML and serve it from a route.

Session 3

Templates with real data

Hardcoded HTML is no use. Jinja lets you put Python-ish logic in your templates.

@app.route("/")
def home():
    expenses = book.all()
    return render_template("index.html", expenses=expenses)
<ul>
{% for e in expenses %}
  <li>{{ e.description }} — £{{ e.amount }}</li>
{% endfor %}
</ul>

{% if not expenses %}
  <p>Nothing yet. Add your first expense.</p>
{% endif %}

Double curly braces print a value. Curly-brace-percent is a statement — a loop or a condition. Note the empty state: an empty screen should tell someone what to do next.

Jinja has filters that transform values in the template — use the pipe character:

{{ e.amount | round(2) }}
{{ e.description | upper }}
{{ e.date | default("no date") }}

Template inheritance is how you avoid repeating the header and footer in every file. Define a base template and extend it:

<!-- base.html -->
<html>
<head><title>{% block title %}Expenses{% endblock %}</title></head>
<body>
  <nav>...shared nav...</nav>
  {% block content %}{% endblock %}
</body>
<!-- index.html -->
{% extends "base.html" %}
{% block title %}My expenses{% endblock %}
{% block content %}
  ...page-specific content...
{% endblock %}

Set up base.html now, before you have many pages. Retrofitting it later means changing every file.

Build this

Real expenses from your ExpenseBook rendered in the page, with a sensible empty state, at least one Jinja filter in use, and a base.html that all other templates extend.

You should now be able to

You can pass data from a route into a template, loop over it, use filters, and use template inheritance to avoid repeating shared layout.

Session 4

Forms, and getting data back

So far data flows one way. A form sends it back.

<form action="/add" method="POST">
  <input type="text" name="description" required>
  <input type="number" name="amount" step="0.01" required>
  <button type="submit">Add</button>
</form>

GET asks for something — it's safe to repeat and bookmark. POST sends something that changes state. That distinction matters: GET requests should be idempotent — calling them once or ten times should have the same effect. POST requests aren't. Use POST for anything that adds, edits or deletes.

from flask import request, redirect, url_for

@app.route("/add", methods=["POST"])
def add():
    description = request.form["description"]
    amount = float(request.form["amount"])
    book.add(description, amount, "general")
    return redirect(url_for("home"))
Why redirect after a POST

If you render a page directly from a POST, refreshing re-submits the form and adds the expense twice. Redirecting sends the browser to a fresh GET, so refreshing is harmless. This pattern has a name — post/redirect/get — and forgetting it causes duplicate-submission bugs everywhere.

For the category, use a <select> dropdown so the user picks from a fixed list. Define that list in your Python code and pass it to the template — don't hardcode the options in the HTML, or changing them later means changing two places:

CATEGORIES = ["food", "travel", "bills", "entertainment", "other"]

@app.route("/add")
def add_form():
    return render_template("add.html", categories=CATEGORIES)
Build this

An add form with a category dropdown (populated from a Python list), a working delete button on each row, and a separate edit page that pre-populates the form fields with the current values. All three use POST and redirect. Add flash messages confirming each action worked.

You should now be able to

You can take form input, act on it, and redirect properly. You can explain idempotency and the post/redirect/get pattern.

Challenge

No hints — pagination

This one is on you

You know routes, templates, query parameters, and slicing. Now combine them. No example code.

Add pagination to the expense list. When there are more than 10 expenses, show them 10 per page with Previous and Next buttons. Requirements:

  • The current page is passed as a URL query parameter: /?page=2
  • Page 1 has no Previous button; the last page has no Next button
  • Requesting a page beyond the end shows the last page, not an error
  • Requesting page 0 or a negative number shows the first page
  • The total count is shown: "Showing 11–20 of 47"

Think through the edge cases before you write the first line.

You're done when

All five requirements above are met, and deliberately testing the edge cases doesn't crash anything.

Session 5

Enough CSS

Put a stylesheet at static/style.css and link it:

<link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">

CSS is a language for describing how elements look. The fundamental concept is the box model: every element is a box with content, padding (space inside), border, and margin (space outside). Knowing this means you understand what padding and margin are actually doing, and why adjusting them moves things the way they do.

The modern way to position things is flexbox. One property on a parent element aligns and distributes its children:

.nav {
  display: flex;
  gap: 1rem;
  align-items: center;
}

On units: px is an absolute pixel. rem is relative to the browser's base font size — so if a user increases their text size in accessibility settings, elements sized in rem scale with it. Use rem for font sizes and spacing, px only for things that genuinely shouldn't scale (like a 1px border).

Ninety per cent of "looks fine" comes from four things: a readable font, a max width so lines aren't enormous, consistent spacing, and enough contrast.

body {
  font-family: system-ui, sans-serif;
  max-width: 700px;
  margin: 40px auto;
  padding: 0 20px;
  line-height: 1.6;
  color: #222;
}
Four hours, then stop

CSS is genuinely absorbing and will eat your fortnight if you let it. Set a timer. Make it clean and legible, then go back to the parts that teach you more.

Build this

Styled well enough that you'd show someone. Not beautiful. Legible and tidy. Use flexbox for at least one layout. Use rem for font sizes. It must be usable on a narrow phone screen — test with your browser's devtools device toolbar.

You should now be able to

It looks deliberately made, you can explain the box model, and you used flexbox for layout.

Session 6

Joining it up

Pull the whole thing together: list, add, edit, delete, filter by category, total at the top, pagination, flash messages, and a proper empty state.

Keep the separation you built in project 4 — routes handle web things (reading the form, redirecting), the ExpenseBook handles logic. If you find yourself calculating totals inside a route, move it.

Add a friendly error page so users never see a stack trace. Flask lets you register error handlers:

@app.errorhandler(404)
def not_found(e):
    return render_template("404.html"), 404

@app.errorhandler(500)
def server_error(e):
    return render_template("500.html"), 500

Test the 500 handler deliberately: add a route that raises an exception (with debug=False) and confirm users see your custom page, not a traceback.

Build this

Full working app: list (paginated), add, edit, delete, filter by category, total at the top, flash messages on every action, a base template shared by all pages, mobile-usable layout, a custom 404 page, and a custom 500 page. README with a screenshot.

You should now be able to

All features work in a browser, your logic code has no Flask in it, and no error ever shows a stack trace to the user.

Traps to avoid

The CSS rabbit hole

Four hours. Timer on.

Logic inside routes

A route should read the request, call your logic, and return a response. If it's doing maths, move it.

Rendering straight from a POST

Refresh re-submits. Redirect instead.
