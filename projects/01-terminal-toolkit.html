Project 01 · Weeks 1–2

Terminal toolkit

Four small command-line tools. Everything you need to write a working program.

init: first commits

The goal of these two weeks is not the tools. It's getting to the point where writing a small program stops feeling like magic and starts feeling like typing.

You'll build four things in one repository. Each is small enough to finish in a session or two, and each adds one new idea. Nothing here has a user interface, nothing looks good, and that's fine — you're learning to make a computer do what you say.

Sessions

  2. Numbers, and why input lies to you

  4. Loops, and repeating yourself properly

Session 1

Printing, variables, and your first script

Before you write anything, understand what you're actually doing. Python is an interpreter — a program that reads your code line by line and executes it immediately. When you type python3 hello.py, you're asking the Python interpreter to open that file and run it top to bottom. That's different from running python3 on its own, which opens an interactive session — a live back-and-forth where each line runs as you type it. Both use the same Python; they're just different ways of feeding it code.

The terminal prompt tells you things worth knowing. The folder name before the $ or % is your current directory — where files get created. pwd prints the full path. ls lists what's here. If you run python3 hello.py from the wrong folder, Python won't find the file. Get comfortable with where you are before you run anything.

print("Hello")

A variable is a name for a value. The = sign means "put this value in this name" — it is not the maths equals.

name = "Sam"
age = 34
print(name)

To put a variable inside a sentence, use an f-string — an f before the quote, and curly braces around the variable:

print(f"{name} is {age} years old")

input() asks the person running the program to type something. Whatever they type comes back as text.

Build this

Write a script that asks for someone's name, age, and city. Then print a multi-line paragraph using all three. Add a bit of personality — if the city is Manchester, note that it's probably raining; if they're under 18, congratulate them on starting early. Three questions, one paragraph, commit it.

You should now be able to

You can explain the difference between running a file and an interactive session, create a .py file, run it from the correct directory, and build a sentence from multiple variables.

Session 2

Numbers, and why input lies to you

Here is the first thing that will confuse you, and it confuses everyone. input() always gives you text, even when the person typed a number.

age = input("Age: ")   # person types 34
print(age + 1)         # TypeError!

Python is telling you it can't add a number to a piece of text. You have to convert it first — int() for whole numbers, float() for decimals:

age = int(input("Age: "))
print(age + 1)         # 35
input() always returns text

input() gives you a string every time, no matter what the person typed. "34" looks like a number, but to Python it's the same as "hello" until you convert it. This rule never changes. Whenever you need a number from the user, always wrap in int() or float().

Python calls these different kinds of values types. You can check a value's type with type():

print(type("hello"))   # <class 'str'>
print(type(34))        # <class 'int'>
print(type(3.14))      # <class 'float'>

Types change what operators do. + on two numbers adds them. + on two strings joins them — this is called concatenation:

print(3 + 3)       # 6
print("3" + "3")   # "33" — joined, not added

This is why types matter. The operator looks the same but behaves completely differently. If you're getting unexpected results, type() is your first diagnostic.

Maths works how you'd expect: + - * /. Two extras worth knowing: ** is "to the power of", and round(x, 2) rounds to two decimal places, which you'll want for anything involving money.

Build this

Build converter.py: ask for a temperature in Celsius, print it in Fahrenheit. Then add kilometres to miles. Round the answers sensibly. Use type() at least once during your debugging — print the type of the user's input before and after converting it, so you can see the change.

You should now be able to

You understand why int() and float() exist, you know what type() returns, and you can explain why "3" + "3" gives "33".

Session 3

Making decisions

if runs a block of code only when something is true. The indentation is not decoration — it's how Python knows what's inside the if.

temperature = 31

if temperature > 30:
    print("Too hot")
elif temperature > 20:
    print("Nice")
else:
    print("Bring a coat")

The comparisons: > < >= <= for size, == for "is the same as", != for "is not the same as".

The classic mistake

One = assigns a value. Two == asks a question. Using = where you meant == is something every programmer alive has done, usually more than once.

You can combine conditions with and and or, and flip one with not. These have a subtlety worth knowing: Python uses short-circuit evaluation. With and, if the first condition is false Python doesn't even check the second — because the whole thing is already false. With or, if the first is true the second is skipped. This matters when the second condition would cause an error if evaluated:

# safe — if items is empty, items[0] is never evaluated
if items and items[0] == "coffee":
    print("First item is coffee")

Two more operators for checking membership — whether a value exists in a collection:

colours = ["red", "green", "blue"]

if "red" in colours:
    print("Red is there")

if "purple" not in colours:
    print("No purple")

in and not in work on strings too — "ello" in "hello" is True.

Build this

Start guess.py. Pick a secret number in the code, ask the person for a guess, and tell them whether they were too high, too low, or correct. One guess only for now. Then extend it: ask for a difficulty level ("easy" for 1–10, "hard" for 1–100), use in to check the input is one of the valid options, and adjust the range accordingly.

You should now be able to

You can write a branching decision, know the difference between = and ==, and use in / not in to check membership.

Session 4

Loops, and repeating yourself properly

There are two kinds of loop and they're not interchangeable. Know which to reach for.

Use a for loop when you know in advance how many times you'll repeat, or when you're going through each item in a collection. It counts for you:

for colour in ["red", "green", "blue"]:
    print(colour)

for n in range(5):      # 0, 1, 2, 3, 4
    print(n)

Use a while loop when you repeat until some condition changes — you don't know how many times in advance:

count = 3
while count > 0:
    print(count)
    count = count - 1
print("Go")

The guessing game is a perfect while — you keep asking until they guess right. Printing a times table is a perfect for — you know you want exactly 12 rows.

break escapes a loop immediately. continue skips the rest of the current iteration and goes back to the top of the loop — useful when you want to skip certain values without breaking out entirely:

for n in range(10):
    if n % 2 == 0:
        continue    # skip even numbers
    print(n)        # prints 1, 3, 5, 7, 9
If it never stops

Press ctrl + c. You've written a loop whose condition never becomes false — usually because you forgot to change the variable it's checking.

To pick a random number, use the random module, which comes with Python:

import random
secret = random.randint(1, 100)
Build this

Three programs: (1) Finish the guessing game — random secret number, keep asking until they get it, count the guesses and tell them at the end. Use a while loop. (2) Build dice.py — ask how many dice and how many sides, roll them all, print each individual roll and the total. Use a for loop. (3) Build times_table.py — ask for a number and print its full times table from 1 to 12, formatted neatly.

You should now be able to

You can write both kinds of loop, explain when to use each, and use both break and continue.

Session 5

Functions

A function is a named piece of code you can run whenever you like. It's how you stop repeating yourself and how programs stay readable past about fifty lines.

def celsius_to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32

result = celsius_to_fahrenheit(20)
print(result)   # 68.0

def defines it, the name in brackets is the parameter — a value handed in when it's called — and return sends an answer back.

print is not return

This trips up nearly everyone. print shows something on screen and gives back nothing. return hands a value back to whatever called the function, so it can be stored and used. A function that prints instead of returning is a function you can't build anything on top of.

Variables defined inside a function are local — they only exist for the duration of that function call. This is called scope.

def add(a, b):
    result = a + b   # 'result' only exists inside this function
    return result

print(add(3, 4))   # 7
print(result)      # NameError — 'result' doesn't exist here

This is a feature, not a bug. If every variable in every function were visible everywhere, programs would become impossible to reason about. Scope means a function can use any name it likes internally without breaking anything outside it. You can hand data in through parameters and get data back through return. That's the whole interface.

Good functions do one thing and have a name that says what that thing is. If you can't name it clearly, it's probably doing too much.

Build this

Two things: (1) Go back through all three tools and pull the logic into functions. Then build tip.py: take a bill total, a tip percentage and a number of people, and return what each person owes. (2) Build unit_converter.py with a menu that offers Celsius↔Fahrenheit, km↔miles, and kg↔pounds. Each conversion must be its own function that returns a value. The menu calls the right function and prints the result — no conversion logic inside the menu itself.

You should now be able to

You can write a function that returns a value, explain why returning beats printing, and explain what scope means.

Challenge

No hints — word counter

This one is on you

Everything you need to complete this, you already know. There is no example code. Work it out, get stuck, look things up, and work it out again. That process is the actual skill.

Build word_counter.py. Ask the user for a sentence. Print three things:

  1. The total number of words in the sentence
  2. The longest word
  3. How many times each word appears (case-insensitive, so "The" and "the" count as the same word)

Test it with a sentence that has repeated words and mixed capitalisation. Make sure it handles an empty input sensibly.

You're done when

It handles a real sentence correctly, repeated words are counted together regardless of case, and empty input doesn't crash it.

Session 6

Tidy up and write it up

Two weeks in, go back over everything with fresh eyes.

Handle bad input. What happens if someone types "banana" when you asked for a number? Right now, a crash. Wrap the risky conversion:

try:
    age = int(input("Age: "))
except ValueError:
    print("That wasn't a number.")

Rename things. Any variable called x, temp or data should be renamed to say what it holds. This is the cheapest possible improvement to code quality.

Write the README. Use the template in the reference section. Include the "what I learned" part properly — it's the bit that's actually worth something.

Build this

Every tool survives nonsense input. Every variable has a meaningful name. README written. Everything pushed.

You should now be able to

Someone else could clone your repo and run all four tools from your README alone.

Traps to avoid

Making it look nice

It's a terminal. Fancy formatting is procrastination dressed as work.

Copying without reading

If you paste something and it works but you can't explain it, you've learned nothing. Delete it and type it out.

Waiting to commit

Commit when it works, and when it half works. Fifteen small commits beats one big one.

If you finish early

  • Give the guessing game a difficulty setting that changes the range.
  • Make the dice roller show each individual roll as well as the total.
  • Add a loop to the converter so it keeps going until the person types 'quit'.
Definition of doneFive scripts run without crashing (hello, converter, guess, dice, times table, tip, unit converter, word counter), each survives nonsense input, the README explains how to run each one, and there are 15+ commits.
